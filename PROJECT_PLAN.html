1. Project Overview｜项目概述

Sywen's Space 是一个以中文内容为主的静态个人博客，按学业（AI、Coding、Research、课程与学习笔记）、生活（个人近况）和我喜欢的（美食、游戏、动漫等杂谈）三个方向记录。

视觉采用“漫画杂志与个人手账”的方向：米白纸张、深色线条、杂志式目录、少量旁白框与原创抽象线稿。通过排版和线条建立个人风格，不依赖大量动漫人物。

已确认的实施基线：

  • 全中文界面与正文，保留英文品牌名称。
  • 副标题采用“学业 · 生活 · 我喜欢的”，Header 英文短句为“Study · Life · Favorites”。
  • 使用原创示例内容与抽象线稿，以书桌 Hero 奠定漫画基调，不等待增强素材库。
  • 保留 Home、Blog、About、Post 四类页面及四篇示例文章；当前学业三篇、生活一篇，我喜欢的允许为空，不要求各分类都有文章。
  • HTML、CSS、原生 JavaScript，无后端、无构建依赖。
  • Gitee 保存代码和提交历史，独立静态托管平台提供公开网址。

工作区检查结果：当前目录为空，尚未初始化 Git，不存在需要兼容的历史实现。

2. Goals｜项目目标

  1. 满足课程对 HTML、CSS、JavaScript、Git、Gitee 和公开访问的要求。
  2. 在首页建立鲜明的漫画线稿风格，在文章页提供稳定的阅读体验。
  3. 通过搜索、组合筛选、主题存储、滚动交互和右键菜单展示真实 JavaScript 能力。
  4. 支持桌面、平板、手机和基本键盘操作。
  5. 新增文章只需复制文章模板、编写正文、登记元数据。
  6. 按 B00–B06 优先完成可提交版本，增强功能不阻塞交付。

3. Non-Goals｜非目标

本期不包含：

  • 登录、注册、评论、后台管理、数据库。
  • 在线编辑器、CMS、Markdown 自动构建。
  • React、Vue、Bootstrap 或大型 UI 框架。
  • 全文搜索服务、分页系统、无限滚动。
  • 全站双语切换。
  • 跨设备收藏、真实点赞统计、访问统计后台。
  • 复杂原创人物设计、背景音乐、鼠标拖尾。
  • 强制长按右键菜单、页面转场系统。
  • 自定义域名购买及自动部署流水线。

4. Course Requirements Mapping｜课程要求映射

2026-09-15 作业基线修订，按最新用户确认：HTML 七页、CSS 布局与主题、JavaScript 主题切换/搜索分类、Git 阶段历史、Gitee 源码、公开 HTTPS 网站，以及书桌 Hero 美术基调。基线完成只以 B06 和 VC1-B 为准。

  • HTML/CSS：源码、七页导航和响应式截图。
  • JavaScript：主题、组合筛选、无结果/重置及降级演示。
  • Git/Gitee：真实里程碑、远端提交与可检查源码。
  • 公开网站：HTTPS 首页及四篇文章深链接，版本对应。

6. Design Principles｜设计原则

  • 70% 简约排版，30% 漫画趣味；Hero 可为 60/40。
  • 正文用留白与层级组织，漫画框用于强调少数内容。
  • 首页允许更活泼，文章页主动降低装饰密度。
  • 大部分文章条目使用分割线，不逐条套厚边卡片。
  • 每个装饰承担明确作用：指引、强调或建立品牌。
  • 交互反馈短而直接，不因动画延迟访问内容。
  • 所有核心页面均可通过正常导航到达。
  • 时间不足时削减装饰和增强功能，不削减核心交互的边界处理。

8.3 线条、阴影与间距

  • 主边框：2px 实线。
  • 文章列表分隔：1px。
  • 圆角：以 0～4px 为主。
  • 按钮硬阴影：默认偏移 3px，主要 CTA 可用 4px。
  • 深色主题硬阴影使用低亮度实色，轮廓由浅色边框保障。
  • 基础间距：4、8、12、16、24、32、48、64px。
  • 动画：120～180ms，主要作用于颜色、阴影和 1～2px 位移。
  • 约 1° 的旋转仅用于小贴纸，不用于正文、导航或菜单。
  • 纸张感以底色为主，稀疏网点只出现在 Hero 插画内。

11. Blog Page Specification｜文章列表页规格

修订说明：以下规格以最新 B/E 实施计划与 视觉规范 v1.1为准；菜单、阅读增强和完整插画库属于基线后任务，旧尺寸/预算冲突由新版替代。

页面结构：

  • 页面标题与简短说明。
  • 带可见标签的搜索输入框。
  • 分类按钮组。
  • 结果数量与重置操作。
  • 单列文章列表。
  • 无结果状态。

分类界面使用：

全部 / 学业 / 生活 / 我喜欢的

行为规则：

  • 默认展示全部四篇文章，按日期倒序排列；同日按 id 排序保证稳定。
  • 输入触发实时筛选，不需要提交按钮。
  • 标题、摘要、标签参与搜索，正文不参与。
  • 去除首尾空格，拉丁字符不区分大小写。
  • 多个空白分隔的关键词采用 AND，每个词可命中任一搜索字段。
  • 分类与搜索共同生效。
  • 切换分类保留搜索词；清空输入保留分类。
  • “重置筛选”清空搜索并恢复全部分类。
  • 当前分类通过底色、字重和 aria-pressed 同时表达。

无结果文案：

没找到匹配的文章。试试其他关键词，或重置筛选。

查询状态：

  • 支持 q 和 category URL 参数。
  • 旧 ai／coding／research 分类参数映射并规范化为 study，保留搜索词；未知分类回退“全部”。
  • 选择“我喜欢的”且无关键词、无文章时，显示“这里还没有文章”及“之后在这里记录喜欢的美食、游戏、动漫，还有一些杂谈。”；有关键词的零结果使用通用搜索无结果提示，保留重置筛选入口。
  • 输入更新后使用 history.replaceState 同步 URL，不为每个字符生成历史记录。
  • 若本地文件环境不允许更新历史，仅停止 URL 同步，筛选继续正常运行。

12. Post Page Specification｜文章详情页规格

修订说明：以下规格以最新 B/E 实施计划与 视觉规范 v1.1为准；菜单、阅读增强和完整插画库属于基线后任务，旧尺寸/预算冲突由新版替代。

页面顺序：

  1. 返回文章列表。
  2. 分类、标题、日期、预计阅读时间。
  3. 示例文章标识。
  4. 正文。
  5. 标签。
  6. 上一篇、下一篇。
  7. Footer。

正文规范：

  • 最大宽度 740px，居中。
  • 每页只有一个 h1，正文从 h2 开始。
  • 支持段落、二三级标题、列表、行内代码、代码块、引用、图片及图注。
  • 代码块保留空白并独立横向滚动，不撑开页面。
  • 图片设置尺寸或宽高比，减少加载后的布局跳动。
  • 不加载语法高亮库，以字体、间距和底色区分代码。
  • 引用块采用左侧实线和“笔记”式标注，不使用大面积装饰框。

上一篇、下一篇定义：

  • “上一篇”指日期更旧的文章。
  • “下一篇”指日期更新的文章。
  • 边界文章不显示不存在的链接，不提供无效按钮。

阅读进度采用顶部 2px 实线，具体计算见第 16 节。

首发不设置侧栏和 TOC；桌面预留的留白用于阅读，不填满。P1 若实现目录，桌面放右侧，窄屏改为正文前折叠目录。

13. About Page Specification｜关于页规格

修订说明：以下规格以最新 B/E 实施计划与 视觉规范 v1.1为准；菜单、阅读增强和完整插画库属于基线后任务，旧尺寸/预算冲突由新版替代。

顺序固定为：

  • 关于我。
  • 学习方向。
  • 兴趣。
  • 最近在做。
  • 常见问答。

内容原则：

  • “技能”以文字分组呈现，不使用百分比进度条。
  • 默认写为“正在学习／关注的方向”，避免虚构熟练程度。
  • 不添加未经提供的学校、地区、邮箱和社交账号。
  • 没有真实社交链接时直接省略，不使用 # 占位。

FAQ 首发三项：

  1. 这里主要写些什么？
  2. 为什么选择漫画线稿风？
  3. 这些文章会持续更新吗？

用静态 Q／A 排版，两种文字标注对应“问／答”；不额外实现折叠逻辑。

14. Global Navigation｜全局导航

Header 包含：

  • 品牌链接，返回首页。
  • 首页、文章、关于。
  • 主题切换按钮。
  • 符合桌面增强条件时显示“快捷菜单”按钮。

规则：

  • 导航为真实链接，当前项使用 aria-current="page"。
  • Header 使用正常文档流，不固定，减少手机阅读遮挡。
  • 手机采用两行紧凑布局，第二行完整展示三个导航链接。
  • 由于导航数量少，本期不实现汉堡菜单。
  • 主题按钮显示动作，如“切换至深色”。
  • 文章页同时提供正文上方的“返回文章列表”。

Footer 包含品牌、年份、课程项目说明及返回文章入口。最终加入真实 Gitee 仓库链接。

15. Custom Context Menu Specification｜自定义右键菜单规格

修订说明：以下规格以最新 B/E 实施计划与 视觉规范 v1.1为准；菜单、阅读增强和完整插画库属于基线后任务，旧尺寸/预算冲突由新版替代。

15.1 启用范围

仅在 (hover: hover) and (pointer: fine) 条件下启用，作为桌面增强。

只有准备显示自定义菜单时才调用 preventDefault()。以下场景保留浏览器原生菜单：

  • input、textarea、select、可编辑区域。
  • 链接、图片、视频、音频。
  • 页面存在非空文本选区。
  • 按住 Shift 右键。
  • 显式标记保留原生菜单的元素。

检查目标元素及其祖先，不只检查直接点击的节点。

不监听触摸长按，不禁用文本选择。媒体条件变化导致不再适用时，关闭菜单并撤销拦截。

15.3 视觉与层级

  • 宽度 224px，最大不超过视口减去两侧 8px。
  • 局部表面色、2px 主线条、4px 硬阴影。
  • 每个操作行高至少 40px，图标附带中文文字。
  • 分组使用细分割线。
  • 使用 position: fixed，挂载到 body，避免祖先裁剪。
  • 层级：常规内容 0、浮动控件 30、阅读线 40、菜单 100、复制降级面板 110。
  • 可用高度不足时菜单内部滚动。

15.4 定位与关闭

  • 按鼠标 clientX/clientY 定位。
  • 测量实际菜单尺寸后限制到视口内，四周保留 8px。
  • 再次右键时更新位置，不叠加实例。
  • 点击菜单项后关闭；异步复制结果在全局状态区反馈。
  • 点击菜单外部、按 Esc、页面或正文容器滚动、Resize、窗口失焦时关闭。
  • 菜单自身滚动不触发关闭。
  • 菜单隐藏时不可点击、不可聚焦。
  • 不添加遮罩阻止页面正常点击。

15.5 键盘行为

通过可见“快捷菜单”按钮使用 Enter／Space 打开；打开位置锚定按钮。

  • 打开后聚焦第一个可执行项。
  • ↑／↓ 循环移动。
  • Home／End 跳到首项／末项。
  • Enter／Space 执行。
  • Esc 关闭并恢复打开前的焦点。
  • Tab／Shift+Tab 关闭并移动到打开前焦点的下一个／上一个正常可聚焦元素，不能困住焦点。
  • 点击外部时不把焦点强制拉回。
  • 执行“搜索”“返回顶部”时，以目标位置为最终焦点。

采用菜单按钮语义、aria-haspopup="menu"、同步的 aria-expanded 和菜单项角色，并实际实现键盘逻辑。交互依据 WAI-ARIA 菜单按钮模式 与 菜单键盘规范。

15.6 复制链接与降级

优先使用 Clipboard API。该 API 要求安全上下文，写入也可能失败，必须处理 Promise 拒绝。MDN Clipboard.writeText

失败时：

  • 显示带标签的只读链接输入框和“关闭”按钮。
  • 聚焦并选中地址，提示手动复制。
  • Esc 或关闭按钮退出，恢复焦点。
  • 输入框保留原生右键菜单。

file:// 模式不尝试复制本地磁盘路径，提示“请在公开网站中复制可分享链接”。

  • 滚动超过 480px 后显示。

  • 返回后聚焦页面主标题，保证键盘使用者真正回到顶部。

16.3 阅读进度

统一采用用户要求的页面滚动进度：

当前滚动距离 ÷（文档总高度 − 视口高度），限制为 0～100%。

  • 使用文档滚动元素获取位置和高度。
  • 分母不大于零时为 100%。
  • 监听滚动，使用 requestAnimationFrame 合并更新。
  • Resize、图片加载后重新计算。
  • 进度条使用 role="progressbar"、中文名称及数值属性。
  • 不设置持续播报的 aria-live，避免滚动时打断阅读。
  • 菜单里的百分比复用同一数值。

明确边界：它表示页面位置，不表示用户已理解或真正读完正文。

16.4 列表与提示

  • 用户搜索词通过文本方式写入页面，不拼接到 HTML。
  • 筛选不移动输入框焦点。
  • 结果数量采用延迟约 300ms 的礼貌播报；视觉列表即时更新。
  • 复制成功等短消息使用统一状态区，不弹出浏览器 alert()。

18. Accessibility｜可访问性

  • 使用 header、nav、main、article、footer 和 time。

  • 每页提供“跳到主要内容”链接。

  • 所有可交互元素提供清晰的 :focus-visible。

  • 正文普通文字对比度至少 4.5:1；大字及关键非文本控件至少 3:1。

  • 不禁用缩放、复制或选择文本。
  • 检查 200% 缩放与窄屏重排。
  • JavaScript 失效时 Header、正文、首页静态文章入口仍可使用。
  • 文章列表页保留四篇文章的静态简版索引；脚本成功初始化后才替换为动态列表并显示筛选工具。

20. Technical Architecture｜技术架构

20.1 运行方式

  • 多页面静态网站，每次导航加载对应 HTML。
  • CSS 自定义属性管理主题和视觉。
  • CSS Grid／Flexbox 管理布局。
  • 经典脚本按功能分文件，函数使用闭包隔离。
  • 仅暴露一个 window.Sywen 命名空间，不引入通用事件总线或组件框架。
  • Header、Footer 保留在每份 HTML 中，不依赖 JavaScript 注入。
